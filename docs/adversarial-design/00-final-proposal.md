## 1. 执行摘要

- 六份提案在「数字带出处、headless vs 留浏览器目检分界」上罕见达标；红队最疼的三刀都砍在「收益写得像量化的、现状写得像精确的、『不破』写得像验过的」——这三点即使六份作者没造假，也都不成立（`06-redteam-attack.md:24/179`）。
- **内容形式**：t1 内核七条（证据分级 / 算不出就如实说 / 算例必选 / 说人话三段禁数字 / 来源纪律 / 双链+反链 / 机器闸门）**一条不退**；只做参数级进化 + 一条「体例合同对齐」新约定（缩写 §5.2）。
- **内容风格**：采纳 t4「条款为骨、场景为钩、反例随行」——正文六段条款不动，叙事钩子只落在「怎么做·什么时候用」入场段，且红线从「禁新增数字」**扩为「禁新增任何可验证事实断言（含日历/时间/情绪统计）」**（吸收 P1-d）。
- **详细内容**：按分布治理、不砍均值；收敛清单具体到 3 对条目 + 3 个超长字段，深化清单具体到 7 条工具 + PATH04 + 章页层声明；新增「冲突链」优先、只给关键条目（吸收 C-2）。
- **展示形式**：先做 3 项成本收益比最优且 headless 可验的——①扫读层最小闭环（t3 I-1+I-4+I-2）②两张决策查表（R-B 凯利/回本）③两张 SVG（R-C 18 场股灾横条/回本曲线）。R-A 分型 / I-3 折叠 / 叙事钩子列为第二阶段，**须先过 canary build**（吸收 P2-a）。
- **破零 JS**：本期**整体驳回**一切破口，维持全站零 `<script>`（吸收 P3-a）；R-B 只做查表版、R-D 只做静态切片版，均零脚本。
- **投资建议红线**：R-B「超过 25% 建议减半」改为自我备忘型提示，不写仓位数值阈值（吸收 C-5）。
- 收口一句话：**先修「体例合同」这件地基，再修「读者 3 秒可扫」这层外壳，展示形式只上能被独立重算/逐字守卫的最小三件，其余全部挂起等目检与收益测量。** 本文件给出可直接抄的决策矩阵（§3）、闭合裁定（§4）、推荐组合（§5）、维护成本表（§6）、反方吸收（§7）、执行顺序（§8）。

## 2. 三条硬闸门（本次收敛的裁决规则，逐条来自红队 §5 并被队长认可）

1. **收益必须给可测量判据**：任何「预期收益 高/中高」的提案，落地前须写死判据——站内无 analytics（全站 0 script），所以判据只允许两类：①headless 可验的结构/算术兑现（例如「lede 122/122 非空」「查表值 == 独立重算」「SVG 数字 == compare.json 逐字」）；②「留浏览器目检」的任务成功率（例如「拿到跌幅→回本答案需几秒/几屏」）。给不出的，收益列按「未证实」降权（`06-redteam-attack.md:55/157`）。
2. **现状一律用 41/122 与 ≈40 条新口径**：禁用 29/122 与 93 条的漂移前数字（`verify-t2.log`）。
3. **任何「不破闸门/不破零 JS」的结论必须过 canary build**：抽样 1 条真实重排渲染壳 → `npm run check` + `astro build` 证明五节/四段式不变式仍 122/122 齐全，才算「不破」；未 build 的放行结论只能标「待 canary 验证」（`06-redteam-attack.md:77`）。

## 5. 最终推荐组合

### 5.1 内容风格（定版）：「条款为骨、场景为钩、反例随行」

- **骨架不动**：六段「怎么做」+ 算例必选 + 说人话三段 + 收益三档 + 来源/备注纪律，全部保留（B1–B11 闸门，`05-tech-feasibility.md:67-81`）。
- **叙事唯一合法落点** = 「怎么做·什么时候用」入场段（`about.md:40-48` 段序不变、不新增节）。四层配额照 t4 §3.1：档案 37 条走「档案路线」、理念 43 条可给一个触发钩子、执行 35 条只在「什么时候用」给具名触发、工具 7 条零叙事配额（`04-style-narrative.md:112-117`）。
- **红线（升级版，吸收 P1-d）**：①禁新增**任何可验证事实断言**（含日历/时间/情绪统计），不只禁数字；②数字只许重排已核值、连同口径与日期出现；③「假设案例」标签升格到句首、不得省略；④反例随行；⑤说人话仍禁阿拉伯数字、白话场景由说人话承担、数字场景由什么时候用承担（`04-style-narrative.md:127`）。
- **试点**：第一条先改 `2008全球金融危机:雷曼那一夜.md`（全站素材最严、数字逐字回源最完整），按新红线复审后作为后续 37 条档案层的样板（§8 阶段四）。

### 5.2 内容形式（定版）：「内核不退，参数归位，合同对齐」

- **内核七条不退**（`01-content-form.md:40-79`）。
- **参数级进化**（E1–E8 按 §3.1 裁定执行）。其中 E3 用 41/122 新口径、不算已落地 12 条。
- **新增一条体例约定（吸收 §1.1）**：凡是 `about.md` 承诺、但闸门不机检的约束（如「这个数怎么用」「常见错有无」「孤岛=0」「速览覆盖」），一律在 about 页显式标「未机检（靠审计）」，不得让读者以为被机器守（`06-redteam-attack.md:39`）。写进同一份 about 重写（E1）。
- **说人话禁数字**精确为「禁阿拉伯数字」：中文小写（跌一半要涨一倍）不被机检、属可允许的表述，但区分表达效率与出处纪律，不主动鼓励绕过（`01-content-form.md:203`）。
- **metric 五值词表**保留；「自由 0 使用」记入参数待议（可缩四值），**属参数、不改内核**（`01-content-form.md:197`）。

### 5.4 展示形式先做 3 项（成本收益比最优，各自可 headless 验）

> 每项下：改动文件 → 大致结构 → 成本 → 验证命令（headless）→ 留浏览器目检项。全部**零 `<script>`、不破闸门**。

#### 项 1 · 扫读层最小闭环（t3 I-1 + I-4 + I-2）

- **改动文件**：`src/pages/[...slug].astro`（lede 回落优先级；来源/备注 section 包 `<details>`；怎么做节首结论行 + 六段 chip 第二行）、`src/lib/headings.mjs`（六段挂稳定 id；复用 `splitSections`/`extractWhenSentence` 同款抽「是什么」首句与「做完你会得到/怎么算过关」首句）、`src/styles/global.css`（抽屉 + chip 样式）。
- **结构**：lede = 手写 lede > 「说人话·是什么」首句 > description；来源/备注默认折叠（summary 常驻）；怎么做节首「做完你会得到：… · 过关标准：…」扫读行。
- **成本**：小（构建期抽取 + 回落优先级 + 样式，约 1–1.5 人日）。
- **验证命令**：
  ```bash
  npm run check                              # 闸门 + compare 逐字，exit 0
  grep -c "<script" dist/**/index.html | grep -v ':0'   # 恒 0，零 JS 不变式
  ```

#### 项 2 · 两张决策查表（R-B 零 JS，凯利矩阵 + 跌幅→回本）
