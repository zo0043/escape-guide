## 1. 三条一手认知研究结论（只引定性，不编数字）

按站规 `about.md:160`，行为科学类出处本环境无法打开学术出版社/原文逐字核验，故**三条全部 B 级定性**：引「作者 + 题名 + 期刊/书名 + 年份」，只引方向性结论，**不引任何具体比例、效应量、样本数、秒数**（t2 笼统引用的「3–8 秒」也在此列，我在本文不把它当证据用）。文中出现的具体数字只有两类：站内复算（§0）与站内文件行号，没有文献统计数。

### 结论一 · 扫描模式（F 形）：先扫后读，且只可靠读到首屏顶部这一段

- 出处：Nielsen, J.（1997）*How Users Read on the Web*，Alertbox / useit.com，1997-10-01；Nielsen, J.（2006）*F-Shaped Pattern For Reading Web Content*，Nielsen Norman Group，2006-04-17。
- 定性结论（B 级）：眼动追踪显示用户**不逐字读，而是扫**；扫读路径近似 F 形——开头几行读得最完整，越往下每一行读的字越少，到页面下方只剩沿左缘的纵向扫视。由此推出网页写作的硬规则：**结论先行 / 倒金字塔**，最重要的那句话必须放在读者一进来就能扫到的最前部，否则它根本不会被读到。
- 证据边界：本条只引「F 形 / 结论先行」这个方向，不引 NN/g 报告里的任何百分比（原文未在本环境逐字核验）。

### 结论二 · 认知负荷与工作记忆：一次只消化一块，连续一次给太多就崩

- 出处：Sweller, J.（1988）*Cognitive Load During Problem Solving: Effects on Learning*，Cognitive Science，12(2)，257–285；Mayer, R. E.（2001）*Multimedia Learning*，Cambridge University Press（分段原则 segmenting principle 所在）；Mayer, R. E. & Moreno, R.（2003）*Nine Ways to Reduce Cognitive Load in Multimedia Learning*，Educational Psychologist，38(1)，43–52。
- 定性结论（B 级）：工作记忆容量**很小且固定**；当一段连续材料在单位时间内超出这个容量，理解就崩塌（「外在认知负荷」）。正面对策是把连续材料**切成小的、读者自定节奏的块**（segmentation / 分段原则）——一次只呈现一块，读通一块再放下一块，比一次性全给更利于加工与记忆。
- 证据边界：只引「容量小、要切块、分段优于连续」的方向，不引任何容量数值或效应量（原文付费墙，未逐字核验）。

### 结论三 · 渐进披露（progressive disclosure）：只给必需项，把进阶/次要内容推到次级层

- 出处：Nielsen, J.（2006）*Progressive Disclosure*，Nielsen Norman Group，2006-12-04（可回溯其 1994 可用性启发式「效率与灵活性」）。
- 定性结论（B 级）：把**进阶（advanced）、不常用（rarely used）、次要**的信息从首屏推迟到次级屏，首层只放完成当前任务必需的内容，并给「点开更多」的清晰入口。新手在渐进披露下比「一次性全给」表现得更好（错误更少、更快上手——方向性，不引具体数字）。
- 证据边界：此项含「新手 vs 专家」的区分——**同一披露策略对不同熟练度读者应不同**：新手要少给，专家要直达。这是后面「按 layer 差分披露」的直接依据。

## 2. 每条结论对应的站内具体缺陷（文件 + 行号）

> 严重度沿用审计符号：🔴 主路径受损 / 🟡 体验与一致性受损 / 🟢 打磨。每条先给证据再给判断。

### 2.1 对应结论一（扫描 / 结论先行）——🔴 结论不在最前，被「怎么做」墙挡住

**R-01 🔴 五节顺序把「怎么做」放第一、「说人话」放第二——最难的一块挡住最省力的一块**
- 证据：五节固定顺序 `about.md:26-31`（`## 怎么做`→`## 说人话`→`## 收益`→…）；抽样实测「怎么做」77–104 行、「说人话」7–8 行（§0.1，`群体心理.md:17-93/94-101`、`泡沫的共同结构.md:21-124/125-132`）；渲染层不改序，`headings.mjs:72-96` 只按 h2 包裹 section、不重排。
- 判断：「说人话·是什么」是本条唯一的一句话结论，却在约第 90 行才出现。F 形扫读下，读者在读到结论之前已经消耗掉扫描预算，退出的决策发生在「怎么做」的第 2–3 屏，而不是在读完结论之后。**结论先行在本站是「标题 + 41 条 lede + 93 条 description」级别的部分补偿，五节层没有兑现。**

**R-02 🟡 「怎么做」六段里的「收获 / 过关」被压在段尾——扫读最该先看的两条在最后**
- 证据：六段固定顺序 `about.md:40-47`：什么时候用(1) → 步骤(2) → 算例(3) → 常见错(4) → **做完你会得到(5)** → **怎么算过关(6)**；「做完你会得到」与「怎么算过关」是第 5、6 位。
- 判断：对扫读者最有信息量、最省力的两段（「我做完会得到什么」「我怎么知道过了」）恰恰排在段尾。这是「倒金字塔」的反面：把「为了什么」藏在「怎么做」之后。

**R-03 🟡 页内目录只有 5 个顶层 chip，90 行「怎么做」节内无次导航**
- 证据：`[...slug].astro:30-37`（TOC 仅 怎么做/说人话/收益/来源/备注 5 项，大师条目加「业绩验证」）、`[...slug].astro:239-241`（section-chips 渲染 5–6 枚）；六段在 `headings.mjs:35-40` 已建 `PARTS` 映射（when/steps/output/pass）但只用于挂 class，**未生成锚点、未进目录**。
- 判断：扫读者只能「跳到 90 行整块」，无法「直达『怎么算过关』『算例』」。六段次导航是 0 成本的既有数据（`PARTS` 映射现成），缺的是把它变成可跳转锚点。

**R-04 🟡 5 秒层对 81/122 条是「低于标题信息量」的占位回退**
- 证据：`[...slug].astro:99`（`hasQuick = lede && when && keyNumber && maxRisk`）、`:166`（`{d.lede ?? d.description}`）、`:86-89`（缺 keyNumber/maxRisk 时回落「收益档位 X · 量纲 Y」「钱·时间·毅力」）；本次复算 41/122 有真 4 卡、81/122 回退（§0）。
- 判断：这 81 条的「结论先行」退化成 `description`（元数据）——它是「给搜索引擎看的一句话」，不是「给人扫的一句话结论」。t2 的「5 秒层」概念是对的，但**5 秒层的内容在 2/3 条目里是空的**。

### 2.2 对应结论二（工作记忆 / 切块）——🔴 单节连续 90 行不分块，一次全给

**R-05 🔴 「怎么做」是一个连续 section，77–104 行不分块、不折叠、无自控节奏**
- 证据：`headings.mjs:72-96` 把整节包成一个 `section.mod-howto`，内部步骤/表/算例全部平铺；抽样：`群体心理.md:17-93` 连续 77 行 = 7 步骤 + 2 张映射表 + 2 个算例；`泡沫的共同结构.md:21-124` 连续 104 行 = 8 步骤 + 七要素表 + 18 场对照表(16 行) + 反例 4 段 + 算例表 A(16 行) + 表 B(5 行)。
- 判断：这是结论二的教科书反例：一段需要「记着前面步骤、同时读当前表格、再对照算例」的材料，被一次性倒进工作记忆。六段标签（`headings.mjs:98-113` 换 `part-label` class）只做了**视觉区分，没做认知切块**——「切块」停在了 CSS 层，没有变成「一次只读一块、读通再展开」的自控。

**R-06 🟡 「来源 / 备注」是查证材料，却与「怎么做 / 说人话」同等默认全展开**
- 证据：`headings.mjs:72-96` 对五节一视同仁包 section、无任何默认折叠；`群体心理` 「来源」20 行、「备注」8 行（`群体心理.md:106-133`）与「怎么做」一样全程展开；来源节本就已降字号降压（audit `02-presentation.md:24` 实测 `mod-source` 整体 0.88rem）。
- 判断：来源/备注是「读者要核验时才需要」的参考层，不是「第一遍读就要消化」的阅读层。把它们全量展开，等于把读者的工作记忆预算分给了「出处核对」这项事后任务。**渐进披露最安全、收益最直接的第一刀不是藏结论，是藏参考节。**

### 2.3 对应结论三（渐进披露）——🟡 有折叠装置，但没有「首层→次级层」的设计

**R-07 🟡 全站 `<details>` 只用于「完整口径」与「长 keyNumber」，五节正文节节全量展开**
- 证据：`[...slug].astro:243-245`（`<div class="entry-body"><Content /></div>` 一次全吐出）；`[...slug].astro:203-207`（唯一的折叠是 quick-card 的「完整口径」details）；t2 复算全站 182 处 `<details>` 绝大多数是 qc-more（`02-presentation.md:26`）。
- 判断：渐进披露的「次级层」目前只存在于**辅助字段**，不存在于**正文本体**。结论三说「把进阶/次要内容推到次层」——本站的进阶内容（算例、18 场对照表、来源、备注）全部处在首层。

**R-08 🟡 layer 四层已必填、已四色，但没有用它决定「默认展开多少」**
- 证据：`about.md:104-113`（layer 理念/执行/档案/工具定义）、`content.config.ts` 必填、`global.css` 四色已落地；但 `[...slug].astro` 全文**无一处按 layer 分叉渲染展开量**（grep 仅 `layer-tag` 色签一处）。
- 判断：结论三的「新手 vs 专家」区分落到本站就是 **layer**：执行层读者要「步骤卡、一次一步」，理念层读者要「先懂原理、容忍长文」。数据里有这个维度（43/35/37/7 齐全），披露层没用它。这也是对 t2 R-A 的独立认知科学背书——R-A 缺的是这条「为什么按 layer 分形态」的一手依据。

**R-09 🟡 移动端首屏被导航 chrome 蚕食，渐进披露的「首层只放必需项」反被导航层占用**
- 证据：`[...slug].astro` 首屏自上而下叠加 read-progress(160) + crumb(161) + header/h1/lede/meta/aliases(164-173) + sticky concl-bar(180-191) + quick-cards(193-218) + path-chips(224-237) + **sticky section-chips(239-241)**，之后才到正文；t2 已警告「sticky 结论条 + section-chips 总高度挤压正文」（`02-presentation.md` §4.2 第 1 条）。
- 判断：这不是「没有首层」，是**首层里塞满了导航，留给结论的垂直空间所剩无几**。结论三要求「首屏只放必需」，而本站首屏的必需项（一句话结论 + 关键数字）与非常需项（路径 chip、5 枚节 chip、别名行）抢同一屏。**留浏览器目检**（375×667 下正文实际起读线在哪一屏）。

### I-1 · lede 由「可选字段」升为「说人话·是什么」构建期自动兜底（结论先行，根治 R-01/R-04）

- 解决：R-04（81 条 5 秒层为空）+ R-01（结论被压在第 90 行）。

- 收益：81 条**零手写成本**获得真「一句话结论」，「结论先行」从 41/122 补到 122/122；`entry-lede`（`[...slug].astro:166`）从「description 元数据」变成「结论」。
- 成本：**小**（构建期一个抽取函数 + 一处回落优先级的改动）。
- 破零 JS：**不破**。
- 与 t 系列关系：对 t1 E3（一屏速览字段补全）的「低成本自动化替代」——与其手写 81 条，不如让闸门已保证存在的「是什么」自动上位；手写的 41 条 lede 仍优先，抽取只作兜底。

### I-2 · 「怎么做」六段升格为两段式次导航（结论先行 + 一次一块，根治 R-02/R-03）

- 收益：扫读者可直达「怎么算过关」「算例」；章首结论行把「为了什么」提到第一步之前，等于在体例不动的前提下局部实现了倒金字塔。
- 成本：**小**（构建期挂 id + 一行抽取 + chip 渲染）。
- 破零 JS：**不破**。
- 与 t 系列关系：t2 R-A 主张「执行层步骤即卡片」——I-2 是 R-A 的**零形态动迁的前置步**：先把六段变成可寻址的块，卡片化（R-A）与折叠化（I-3）都建立在这组 id 上，不重复造轮子。

## 5. 收口：给主编的一句话立场

**三条证据（F 形扫描 → 结论先行；工作记忆有限 → 一次一块；渐进披露 → 首层只给必需）落到本站只有一句话：结论被压在 90 行「怎么做」之后、81/122 条没有真「5 秒层」、90 行的「怎么做」一次全给——问题不在文本长短，在信息没有被切成读者大脑能接住的层。** 因此我主张的最小闭环是：**「是什么」自动顶到 lede（I-1）→ 「怎么做」长节按段折叠（I-3）→ 「来源/备注」默认收成查证抽屉（I-4）→ 六段次导航（I-2）→ 按 layer 定默认停靠层（I-5，与 t2 R-A 合并）→ 加一枚扫码入口把条目交给手机（I-6）**。硬约束只有一条：**「说人话」与「收益」这两个降负荷节永不可折叠；藏参考、叠动作、不藏结论。** 这六条全部零 JS、不破闸门体例、不砍任何一条内核——是在 t1「守成」与 t2「重构」之间，由读者大脑划出的第三条路：**内核不动，但每一条必须在读者 3 秒内可扫、一块一块可读、次要内容可藏。**
