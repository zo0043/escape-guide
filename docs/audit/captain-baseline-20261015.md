## 3. 本机实测：缺陷与风险

### 3.1 环境级（会误导所有"验证"结论，**必须让每个成员知道**）

- **Landlock 沙箱会让 `npm run build` 假失败**：Astro `ssrMoveAssets` 跨目录 `rename()`
  被沙箱以 **伪 `EXDEV`** 拒绝（`dist/.prerender/_astro/*.css` → `dist/_astro/*.css`）。
  - 实证：同目录内 rename 成功（`SAME_DIR_OK`），跨目录 rename 失败（`EXDEV`）。
  - 实证：在 `/tmp` 独立目录构建**同样失败** → 与工作区无关，是沙箱策略。
  - **危险点**：报错长得像"磁盘/挂载/项目坏了"，实为沙箱。**若误判，会把不存在的"构建坏了"写进报告。**
  - 本会话已切换 `danger-full-access` 后构建正常（139 页）→ 本副作用已被消除，但结论请以此为准。
- **`npm run check` 的退出码不能靠管道读**：`npm run check:canary` 实测 `EXIT=0` 而输出是判红
  （`tail` 吃掉了真实退出码）。**取退出码必须用 `${PIPESTATUS[0]}` 或不经管道重定向。**

## 4. 待核的关键结构性问题（本审查的重点）

1. **闸门全绿但内容可能错**：闸门 24–25 条规则里**没有一条验证算术或事实**。A2 即此缺口的活证据。
   → 需回答：还有多少条"每行单算对、跨行口径错"的算例？（124 条里"怎么做→算例"是必选段）
2. **书目从未外核**：106 个书名 / 75 条条目。A1 已证伪 1 本 → 其余 105 本的外核覆盖率是 **0%**。
3. **"可复算"主张与工序话术的边界**：65 条含构建期工序数字。哪些是"诚实的一手源证据链"（该保留），
   哪些是"内部工序外露"（A3 该删）？**需要一条可判定的标准，而非一刀切。**
4. **README 声称的"可验证性"三支柱**（数字逐字回源 / 证据分级 / 闸门强制）中，
   只有第三支柱是机器守的，且只守机械层——第一、二支柱实际靠人。

## 7. 审查后记：本次深度审查的环境与运行事实（2026-10-15 补充）

本节记录本次 agent team 审查的运行事实与踩坑，供后续复用。

### 7.1 团队路由陷阱（实测，影响任何 AgentTeams 运行）

1. **`zero43/deepseek-v4.1-flash` 不能用于团队成员**：全员 3 次挂同一 400
   `The reasoning_content in the thinking mode must be passed back to the API`。
   该模型思考模式要求跨工具轮回传 `reasoning_content`，而 DSH 的 `dsh-llm-pi-ai`
   适配器以 `thinkingSignature` 重放推理块；重放保真度一旦丢失，请求即硬失败。
   实测该模型**无法关思考**：`reasoning_effort: "off"` 被拒
   （`provider does not support reasoning effort "off"`）→ 该路由的失败是**固有的**，不是偶发。
   **结论：团队路由改用非 DeepSeek 模型。**
2. **`glm-5.3` 在目录里但无可用通道**：`model_not_found / No available channel for model glm-5.3`。
   目录列出 ≠ 实际可用，需实测。
3. **实测可用路由**：`qwen3.8-27b`（多轮工具调用稳定，本次主力）、`qwen3.8-max`、`grok-4.7`。
   **实测不可用**：`mimo-v2.6-pro`（quota exhausted）、`step-5-preview`（需订阅）、
   `kimi-k3` / `gpt-5.6-terra`（返回体畸形）。
4. **并发 3 会 429**（`429 RATE_LIMIT`）——独立复现了 `docs/handover.md` §2 记录的并发上限＝2。
5. **调度器会为 idle 成员自动认领共享池任务**，可能把任务派给「专业不对口」的成员
   （本次两次把 IA 任务派给工程成员）。**对策：让成员的 executionPrompt 覆盖它可能被派到的
   所有任务，使任何派发都无害**，而不是依赖 assignee 精确绑定。
