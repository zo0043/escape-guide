## 总原则

1. 加的是**可验证的具体性**，不是形容词。每段新内容要么有原文/数字/可复算的推导，要么如实标注（「假设案例」「暂未找到可核实的反例」）。
2. **算例是假设案例**：用具体数字（金额/价格/日期/步骤），但**不指向任何真实公司、真实代码**；正文显式标注「（假设案例）」。算例里的数字**不改变证据等级**（等级仍跟来源走）。
3. 数字出现位置：怎么做（含算例）/ 收益 / 来源 / 备注 均可；**说人话仍禁阿拉伯数字**（闸门机检）。
4. 不改动 front matter 的 `title` / `chapter` / `weight` / `aliases`（URL 与目录结构必须稳定）。`description` 可更新（须反映 v2 内容、不含 `[[…]]`、非空）。
5. 每条写完必跑：`node scripts/check-content.mjs --only "<文件名特征串>"`，全绿才算完成。

## 五节 v2 格式

### 怎么做

四段式保留，新增两段。段顺序固定：

```text
**什么时候用** → **步骤** → **算例** → **常见错** → **做完你会得到** → **怎么算过关**
```

- **步骤**：保持编号动作，每条可独立执行、可判定做没做。
- **算例**（必选，闸门机检 `**算例**` 标记）：一个完整假设案例——给初始条件（金额、价格、仓位），逐步写出每个动作的输入与输出数字，读者照着能复算出同样的结果。建议用表格（| 动作 | 数字 |）。
- **常见错**（建议写，不机检）：1–3 条，多数人在这一步会做错什么。
- **做完你会得到**：具体到「清单里有哪些字段 / 哪个数字 / 用来做什么决定」，不许只写「一张清单」。
- **怎么算过关**：可自查、可判定的标准。
- **汉字数下限**：「怎么做」整节汉字数 ≥350（闸门机检，只数汉字，标点/数字/表格符号不计）。

### 说人话

从 1 段扩到 **3 短段**（汉字数 ≥ 150，闸门机检、只数汉字；仍禁阿拉伯数字）：

1. **是什么**（保留原有比喻，可精炼）；
2. **为什么发生**（机制：它具体怎么把人坑了，一步步）；
3. **什么时候不成立**（边界：什么情形下这条建议会失灵或需要修正）。

### 收益

三档制**不动**。`量级` 档结尾加一句「这个数怎么用」（这个数对读者决策的作用）；`无量级（方向性）` 档保持现状即可。

### 来源

不动（纪律区）。新条目按 about 页来源规则：原始出处、每个链接真的 `curl` 打开过 + 标「核对于 YYYY-MM-DD」、C 级如实写「无一手出处」、打不开等于没有来源。

### 备注

扩到 **3–5 个列表项**（闸门机检 ≥ 3 个列表项），内容从这四类里取：

- **适用前提**：什么情况下这条不适用；
- **已知反例**：至少 1 条真实案例或真实情形；确实没有就如实写「暂未找到可核实的反例」——**不许编**；
- **关联条目**：`[[…]]`（至少 1 条，配合出度要求）；
- **有效期**（规则类条目）：核对于何时、什么情况会变。

## 双链（轴 3：网络做实）

- 每条**出度 ≥ 2**（唯一目标数，闸门机检）。
- 每条任务书里带**链接地图**（每条 2–4 个指定目标）：**可加不可减**，指定目标必须全部出现。
- 写法：`[[完整标题]]` 或 `[[别名]]`（与现有条目一致）。
