这里是 **A股散户逃生指南**，2026-10-11 从 [blog.zero43.top](https://blog.zero43.top/) 拆分出来独立成站。

它借用的是 [HowToLiveBetter](https://github.com/eternity4719/HowToLiveBetter) 那套**条目骨架**（每条写清成本、收益、证据等级、原始出处），但题材、内容、判据全部另起一套——不搬运它的任何正文。

## 本站不是什么

> 2026-10-15 审查（docs/20261015-escape-principle-review.md §3 项 7）主张清单，照单定稿。两句强句（「不是不亏保证」与保命钱那句）为信任核心，不软化。

- 不是预测工具：不抄底不喊顶，不答「到底了吗」；只提供「跌了怎么办」+「历史上这么跌过 N 次，可复算」。
- 不是荐股/荐时工具：无个股、无目标价、无「现在是买点」。
- 不是不亏保证：逃生上限 = 亏损不毁生活；**用保命钱入市者，本站任何方法都救不了你**。
- 不是实时媒体：崩盘期间不实时评，档案只写事后已定案。
- 不是收益课程：赚钱理念条目保留只因低成本/分散/长期本身是防守；本站不承诺收益。
- 不是知识量百科：124 条冻结，新增仅限 3 触发 + 退出端例外。
- 不是平台：无社区/评论/追踪——零 JS 即逃生身份：站只保护资金，不经营注意力。
- **不适用于以投资收入维持生活者。**

## 双链怎么用

本站条目之间用 `[[条目名]]` 互相引用：写标题或别名都行，不区分大小写。
写错的条目名**不会产生死链**，而是渲染成橙色虚线的「未收录」标记；
每个条目底部会自动列出**反链**（哪些条目提到了它）。

想写字面的 `[[方括号]]`：用行内代码，或在源文件里写 `\[[方括号]]`。

## 条目格式

> **本节与 `scripts/check-content.mjs` 保持一致，两者不一致时以闸门为准**（当前 v6，23 条规则，2026-10-13）。
> 闸门由 `npm run build` 在 `astro build` 之前调用——不是外挂脚本，所以绕不过去：
> 缺任何一节、缺任何一段、段顺序不对、任何字段取值非法，构建都会直接失败。

每条正文固定五节：

```text
## 怎么做     —— 六段固定顺序，见下（**算例** 与 **常见错** 均为必选段）
## 说人话     —— 三段段首命名（是什么/为什么发生/什么时候不成立），不许出现阿拉伯数字
## 收益       —— 三档制，见下（量级档必须带「这个数怎么用」收尾句）
## 来源       —— 原始出处 + 核对日期（C 级如实写「无一手出处」+ 等级说明）
## 备注       —— ≥3 个列表项（闸门机检数量）：适用前提/已知反例/关联条目/有效期
```

### 「怎么做」必须是六段固定顺序

概念类条目最容易写成一句格言——读起来像道理，却没有任何可执行的东西。
所以这一节强制六段固定顺序，**缺一段、或顺序不对，构建就失败**
（v2 把 **算例** 设为必选段；v3 把顺序固定——段齐了但排错位置同样判红；
v6 起 **常见错** 也升格为必选段——它实测早已 122/122 全有，规格此前停在「建议写」）：

| 顺序 | 段 | 要求 |
|---|---|---|
| 1 | **什么时候用** | 翻这条的场景（触发条件，不是原则） |
| 2 | **步骤** | 编号动作，一次能做完 |
| 3 | **算例** | **必选**（闸门机检 `**算例**` 标记）：一个可复算的假设案例——给初始条件（金额/价格/仓位），逐步写出每个动作的输入与输出数字，读者照着能复算出同样的结果；显式标注「（假设案例）」，算例数字不改变证据等级；真实数据复算型标注「（官方数字的复算）」并逐字引一手源（详见 docs/content-v2-spec.md 总原则第 2 条例外） |
| 4 | **常见错** | **必选**（闸门机检 `**常见错**` 标记，v6 升格）：1–3 条，这个场景下最常犯的错 |
| 5 | **做完你会得到** | 手上多出什么（一张清单／一个数字／一份凭证） |
| 6 | **怎么算过关** | 可自查的验收标准，不达标就是没做完 |

另外几条机检规则（v2/v3/v5）：

- **汉字数下限**（只数汉字，标点/数字/表格符号不计）：「怎么做」≥350 汉字，「说人话」≥150 汉字。
- **出度双链 ≥2**（按唯一目标计数）：本条必须链到至少 2 个其它条目——手册感 = 网络感。
- 双链必须写全 `[[目标]]`；双链后紧跟半角括号（`[[目标]](注释)`）会被解析成死链，注释一律用全角（`[[目标]]（注释）`）。
- **裸 URL 后不要紧跟全角标点**：`https://…。` 或 `"https://…"。` 会被 GFM 自动链接把标点和后面的中文一起吞进 href，点了就是 404（违反「打不开的链接等于没有来源」）。修法：URL 用 `<URL>` 包裹，或在 URL 与标点之间留一个空格。
- **对照表的 `src` 必须能被条目解析**：`src/data/compare.json` 每一行的 `src` 要能被某个条目的标题或别名解析到（含半角/全角冒号的别名差异），解析不到那一行首列会静默失去链接——所以给全角标题补半角别名是**内容纪律**，不是可选项。

### 「说人话」必须是三段段首命名

这一节只负责解释——**不许引入收益栏之外的新数字**（「说人话」里出现阿拉伯数字，构建直接失败）。三段必须段首命名：

```text
是什么：          一句话说清这条在说什么
为什么发生：       用大白话讲清为什么这样、为什么有效
什么时候不成立：   这条失效的边界条件
```

### 「收益」必须是三档之一

这一节曾经写过「按口径给量级」，但实测 41 条通篇没有一个数字，全是形容词。
现在只有两种合法档位（闸门按开头的字面判定）：

```text
量级（口径：亏损）：<必须真的含阿拉伯数字>……这个数怎么用：……
量级：<历史写法，闸门仍接受，但新条目一律写全「（口径：X）」>……
无量级（方向性）：<说明为什么算不出>
```

- 写「量级」却通篇没有阿拉伯数字，构建会直接失败——那又变回形容词充数了。**算不出就如实说算不出**，这份指南可信度靠的就是这条。
- 行内「量级（口径：X）」的 X 必须 ∈ 五值词表（亏损|收益|时间|自由|处罚），且与 front matter `metric` 逐字一致（不一致构建失败）；量纲说明写在冒号之后的正文里，不要塞进括号。
- 「量级」档结尾必须带一句**「这个数怎么用」**（这个数对读者决策的作用）——**v6 起闸门机检**，缺这句构建直接失败；「无量级（方向性）」档不受此约束，保持现状即可。

front matter 完整模板——照抄即可过闸门（临时 canary 条目已按本模板验证过，见交付日志）：

```yaml
title: "条目标题"            # 必填；双链写标题或别名都行，不区分大小写
description: "一句话摘要"      # 必填；不许含 [[…]]（该字段会原样进入 meta/og/RSS，泄漏字面括号）
chapter: "03 人性与心理"      # 必填，六值白名单：01 市场与周期/02 理念与理论/03 人性与心理/04 规则与制度/05 风险与防守/06 实务与查证
date: 2026-10-12             # 可选：日期
weight: 50                   # 可选：章内排序权重（大者在前）
layer: "执行"                # 必填，四值枚举（定义见下表）；闸门机检，缺失/非法构建失败
aliases: []                  # 可选：双链别名
tags: []                     # 可选
cost: { money: "0", time: "少", will: "否" }   # 钱=0|少|多  时间=少|中|多  毅力=否|些|是
gain: "大"                   # 大|中|小
metric: "亏损"               # 亏损|收益|时间|自由|处罚 —— 收益数字的量纲，与正文行内口径逐字一致
evidence: "B"                # A|B|C（见「证据等级」）
disputed: false              # 可选：A/B 级存在反方证据时置 true
checked: 2026-10-08          # 来源核对日期，对所有条目必填（见「来源规则」）

# ── 一屏速览字段（全部可选；渲染为宽屏桌面一屏的四张事实卡，窄屏 2×2 布局；缺省回落到 成本/收益/证据 结构化事实）──
lede: "一句话结论"            # 这条到底在说什么
when: "什么处境下用这条"        # 这条适用的处境（一句话）
keyNumber: "一个数字（含口径）" # 最能说明问题的那一个数（含口径）
keyFigure: "大数字"           # 可选：显式指定速览卡的大号数字；声明了就必须是 keyNumber 的逐字子串（闸门机检，防漂移）；不声明则回退机械提取
maxRisk: "用错这条会怎么死"     # 最大风险（一句话）

# ── 崩盘峰谷数字条（可选，仅灾难档案适用；渲染为 quick-cards 后的三列 hero，缺省不留痕迹）──
# 五个数字必须从收益节首句/keyNumber 逐字抄（含全角 −，不改位数/口径）；recover 是收益节收复/未收复句的浓缩
# crash:
#   peak: { v: "381.17", d: "1929-09-03" }   # 峰值点位 + 日期（keyNumber 逐字子串，闸门规则 24 机检）
#   drop: "−89.19%"                          # 最大跌幅（keyNumber 逐字子串）
#   bottom: { v: "41.22", d: "1932-07-08" }  # 谷底点位 + 日期（keyNumber 逐字子串）
#   recover: "回到前高 1954-11-23(约 25.2 年)" # 可选：收复/未收复句浓缩（长句，不机检）
```

**字段枚举一览**（闸门逐项校验，取值非法或必填缺失都会构建失败）：

| 字段 | 必填 | 允许值 |
|---|---|---|
| `title` | ✅ | 任意；双链写标题或别名都行，不区分大小写 |
| `description` | ✅ | 非空；不许含 `[[…]]` |
| `chapter` | ✅ | 01 市场与周期 / 02 理念与理论 / 03 人性与心理 / 04 规则与制度 / 05 风险与防守 / 06 实务与查证 |
| `layer` | ✅ | 理念 / 执行 / 档案 / 工具（定义见下表） |
| `cost.money` / `cost.time` / `cost.will` | ✅ | 0\|少\|多 / 少\|中\|多 / 否\|些\|是 |
| `gain` | ✅ | 大 / 中 / 小 |
| `metric` | ✅ | 亏损 / 收益 / 时间 / 自由 / 处罚 |
| `evidence` | ✅ | A / B / C（见「证据等级」） |
| `checked` | ✅ | 核对日期；对所有条目必填，C 级也不例外 |
| `disputed` | 可选 | true / false（缺省 false；A/B 级存在反方证据时置 true） |
| `date` / `weight` / `aliases` / `tags` | 可选 | 日期 / 章内排序权重 / 别名数组 / 标签数组 |
| `lede` / `when` / `keyNumber` / `maxRisk` | 可选 | 一屏速览四字段（字符串）；缺省回落到 成本/收益/证据 |
| `keyFigure` | 可选 | 字符串；声明了就必须是 `keyNumber` 的逐字子串（否则判红） |
| `crash` | 可选 | 崩盘峰谷数字条 `{peak:{v,d}, drop, bottom:{v,d}, recover?}`（全字符串，仅灾难档案适用）；声明时 `peak.v/peak.d/drop/bottom.v/bottom.d` 五个数字必须都是 `keyNumber` 的逐字子串（否则判红，含全角 − 号）；`recover` 是收益节收复/未收复句的浓缩，不机检；数字必须从收益节首句/keyNumber 逐字抄，不诚实适配的条目不写（宁缺毋滥） |

**`layer` 四层定义**（与 `src/content.config.ts` 注释逐字一致，改一处必须改另一处）：

| layer | 定义 |
|---|---|
| 理念 | 讲清「为什么会这样」的概念/机制/理论 |
| 执行 | 可以直接照做的动作、纪律、流程、自查 |
| 档案 | 按人或按事件立档，核心是「发生过什么 + 可核数字」 |
| 工具 | 去哪里查、怎么查的入口（查* 类） |

归类按条目性质，章节只作默认值。**不要合并同题条目**——本站刻意把同一主题拆成理念层与执行层两条，`layer` 是读者唯一的层级信号。

### 哪些是机器守着的，哪些只是承诺（未机检）

**别把「写在 about 上」当成「被机器守住了」。** 闸门只机检**结构标记的存在与顺序、字段取值、字数下限、双链出度、可机检的字面形状**；它不判断语义对不对，也不看页面上真的渲染成什么。下面这张表把两类分开——凡是没进闸门的约束，靠的是人工审计，不是构建：

| 约束 | 谁在守 |
|---|---|
| 五节齐全 / 六段固定顺序 / 算例必选（v2） / 常见错必选（v6） | **闸门**（规则 1 / 14 / 7 / 23） |
| 说人话三段命名 / 禁阿拉伯数字 / 「怎么做」≥350 与「说人话」≥150 汉字 | **闸门**（16 / 4 / 10、11） |
| 量级档「这个数怎么用」收尾句（v6） | **闸门**（22） |
| 收益三档合法开头 / 行内口径 ∈ 五值且与 `metric` 逐字一致 | **闸门**（3 / 15） |
| front matter 全字段枚举与必填（含 `description`、`checked`、`keyFigure ⊂ keyNumber`） | **闸门**（front matter 段） |
| `crash` 声明时五个数字 ⊂ `keyNumber`（v8，`recover` 不机检） | **闸门**（24） |
| `layer` 必填 + 四值枚举 | **闸门**（20） |
| 备注 ≥3 列表项 / 出度双链 ≥2 / 双链后禁半角括号 / `[[` 未闭合 / 裸 URL 后不加全角标点 | **闸门**（8 / 9 / 12 / 13 / 18） |
| 双链目标未收录（渲染成「未收录」标记） / `description` 含 `[[…]]` | **闸门** 但只报 warning（6 等），不阻断构建 |
| A/B 级有反方证据却没标 `disputed: true` / 「无公开统计」没写清是哪种「没有」 | **闸门** 但只报 warning（17 / 19），真假由人工复核 |
| 「算例」是否真的可复算、数字是否真的逐字来自所引一手源 | **人工审计**（闸门只看 `**算例**` 标记在场） |
| 「这个数怎么用」那句是否真的说清了这个数对决策的作用 | **人工审计**（闸门只看这句字面在不在） |
| 「常见错」是否真的是这个场景下最常犯的错 | **人工审计**（闸门只看标记在场） |
| 语义正确性：标记齐了但意思写反、口径虽然合法但用错含义 | **人工审计**（闸门只查标记与取值，判不了语义） |
| 孤岛（无任何条目链接它）= 0、同题对必须双向互链 | **人工审计**（语义判断，硬编码进闸门会制造误报） |
| 一屏速览字段（`lede/when/keyNumber/maxRisk`）的覆盖率 | **人工审计**（4 个字段本就是可选，补全是内容工作，不是格式问题） |
| 原始出处是否真是一手、链接是否真打得开 | **人工审计**（「核对于」是自定句式，是提醒不是证明，得真的 `curl` 过） |

> 这是本站的一处**自觉的**取舍：闸门管得住「格式不走样」，管不住「内容是对的」。所以每个批次改写完都要跑人工审计（`docs/audit/`），两者的分工写在这里，免得读者以为整站被一套脚本守死了。


## 证据等级

等级只回答一个问题：**这个说法的数字可不可信**。它不衡量收益大小。

| 等级 | 含义 |
|---|---|
| **A** | 有一手数字：官方统计（上交所统计年鉴、证监会、中国结算）或同行评议研究，正文必须给出具体数字；推导型/定义性事实见「来源规则」（数字由推导确定） |
| **B** | 有监管原文或已生效的规则、判决，或同行评议文献/书目引用（只引定性结论、不引具体统计数），事实确定但无法量化 |
| **C** | 经验或行业共识，没有可直接引用的出处 |

### 条目级等级怎么定（聚合规则）

一条条目往往引用多个来源，等级没法逐个来源都取。本站只用一种算法，写在这里免得读者猜：

> **`evidence` 取「正文主张的主要依据」的等级。** 判断方法：把这条最核心的那个数字或那句话换掉，看条目主张还站不站得住——那个来源就是主要依据。
> **背景性与叙事性来源允许低一级，但必须在「来源」节逐条标级**（站内写法如「机构与失业率叙事为 A/B」「护送船团机制为 B/C」）。
> **含低一级来源时不降级、不改判**：A 级条目里出现 B/C 级背景，不因此变成 B。

由这条直接得出的三个推论：

- **A 级是「核心数字 A」，不是「全部来源 A」。** 两条同为 A 的条目，一条可能含 C 级背景、一条不含，这不妨碍它们同为 A；读者该看的是核心数字那一行的等级。
- **转引不升格。** 引用站内其它条目的数字时，**那一项的等级不高于被引条目的核验强度**；凡本条没有亲手复算的转引，按书目/二手引用处理、最高 B——它不会因为被写进一条 A 级条目就变成 A。所以 [[泡沫的共同结构：五次崩盘里的同一套剧本]] 拿五场 A 级崩盘当骨架，仍记 B。
- **降级只发生在主要依据本身降级时**（来源打不开了、原研究被撤稿、规则修订了），并且要同步更新 `checked`。

### C 级拆三个子档

「C 级」一条里其实装着三种不同的情况，读者看到的「不可核」不是同一件事。本站把 C 拆成三个子档；**front matter 的 `evidence` 仍只写 `C`**（不改字段），子档写在「来源」节，句式固定为 `等级说明：C1 史料不可核`，可机读检索：

| 子档 | 含义 | 本站实例 |
|---|---|---|
| **C1 史料不可核** | 事件是真的，但当时没留下可核的价格序列或账目；引用的是后世研究与辞条 | [[1637郁金香狂热:第一场有记录的泡沫]] |
| **C2 民间共识无出处** | 共识性说法（祖训、口诀、行业或舆论俗称），没有可引用的一手出处，也不编造链接 | [[别满仓，别单吊]] |
| **C3 二手通说待核** | 机制表述来自二手通说，一手研究没取到；只引方向、不引数字 | [[情绪与决策:压力之下人退回习惯]] |

C 级条目的例外不变：「来源」一节如实写「无一手出处」，**不编造链接**（见「来源规则」）。

**「收益大」不等于「证据 A」**——这是两个正交维度。另有一个独立维度是 `metric`（口径）：允许取值是「亏损、收益、时间、自由、处罚」，指这条说法最终落在哪个量纲上，**不同口径之间不做比较**（「少亏 5 万」和「少坐 2 年牢」不能折算）。

> **词表 ≠ 用量**：上面五个是**允许写**的取值，不代表每种都有条目在用。写不存在的口径会让构建失败。

## 来源规则

- 只引**原始出处**：证监会 / 交易所 / 中国结算 / 统计局 / 最高法等官方文件，同行评议的原始论文，或人物本人的**原始文本**（见下条）。
- **原始文本类出处**（人物自己的出版物 / 公开信件，如投资理论）：书引「作者 + 书名 + 年份」（能确定章节则带章节），并在「来源」注明「书目引用，原文未逐条核对，无 URL」；公开信件用 `curl` 对官方原文核验并附 URL。此类出处默认 **B 级**（归属事实确定、不可量化）；带独立可核一手数字时才可升 A 级。
- **推导型出处**（数学/定义性事实，如亏损回本不对称、期望值）：「来源」写推导过程（公式 + 数值示例），无需外部出处，记 **A 级**——数字由推导确定，比任何文献都确定。
- **行为科学类出处**（认知偏差/群体心理）：同行评议论文引「作者 + 题名 + 期刊/年份」，原始文本按书目规则；本指南当前环境无法打开学术出版社原文核验数字（2026-10-11 实测：Science/Springer 均为付费墙或机器人验证页），故此类条目**只引定性结论、不引具体统计数**，默认 **B 级**。
- **不引**知乎、微信公众号、股吧、财经自媒体等二手转述——即使它们说的是对的，也要回到它引的那份原件。
- **C 级条目的例外**：「来源」一节如实写「民间共识（C 级），无一手出处」，**不编造链接**。
- `checked` 对**所有条目必填**（C 级也不例外）：填你核对、写下这条的日期——A股规则会变，这个日期就是说法的保质期。
- 每个**带链接**的来源都要标「核对于 YYYY-MM-DD」，并且真的用 `curl` 打开过——**打不开的链接等于没有来源**。
- A 级条目的「重跑命令」在页面里**默认折叠**（来源段里的「▸ 重跑命令（展开核对）」点开即可，与条目原文逐字一致）——展示层折叠，不是删证据：命令本体仍在仓库条目内，任何人可复算。

### 三种「算不出」的标注，语义不同

正文里出现这三种标注时，它们不是同一种「没有」，别混用：

| 标注 | 含义 | 本站实例 |
|---|---|---|
| **需人工核对** | 有口径，但本站取不到或没逐条核（付费墙、反爬、原文太长） | 标普两点位需人工核对 |
| **无公开统计** | **口径本身不存在**——没有任何机构发布过这个数 | 1993–94 年散户平均亏损 |
| **无单一官方口径** | 各家都在发布，但统计范围与定义不同，无法相加或对比 | 各国救助规模合计 |

这三条的权威定义见 [[1993到1994:千点到三百点]] 与 [[2008全球金融危机:雷曼那一夜]]；上面这张表是图例，不是新规定。拿不准时按最谨慎的那条写，**不要用「无公开统计」去描述一个只是你没拿到的口径**。
